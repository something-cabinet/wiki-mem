# Wiki Memory Engine (wm)

A local knowledge graph engine for AI-assisted project management. **wm** provides an MCP server that indexes markdown wiki pages into a typed graph with BM25 search, optional semantic search via ONNX embeddings, and a full CLI/TUI for interactive use.

## Install

```bash
npm install -g @something-cabinet/wm-cli
```

Or build from source:

```bash
cargo install wm-cli
```

## Quick Start

```bash
# 1. Initialize a project
wm init

# 2. Start the MCP server (for AI agents)
wm mcp

# 3. Or use the interactive TUI
wm
```

## Setup Workflow

### 1. Initialize

```bash
wm init                    # Interactive wizard — prompts for model, git tracking, platforms
wm init --no-wizard        # Headless — use defaults
wm init my-project         # Name the project
```

The interactive wizard asks:
- **Enable semantic search?** → Select ONNX embedding model (bge-small-en-v1.5 / all-MiniLM-L6-v2 / bge-base-en-v1.5)
- **Git tracking mode?** → `git-tracked` (track all) / `git-ignored` (ignore generated files) / `none`
- **Platform agent files?** → Generate configs for Claude Code, OpenCode, Kiro, Gemini, Copilot, or generic agents

### 2. Generate Platform Config

```bash
wm setup claude            # .mcp.json + .claude/skills/
wm setup opencode          # opencode.json
wm setup codex             # .codex/config.toml
wm setup all               # All platforms
```

This generates MCP configs so AI agents can connect to `wm mcp`.

### 3. Create Pages

Wiki pages are markdown files under `.wm/wiki/` with YAML frontmatter:

```yaml
---
title: My Page
type: concept        # task | spec | concept | pattern | decision | howto | reference
status: draft        # draft | reviewed | approved | done | in-progress | todo
tags: [tag1, tag2]
---
```

Create via CLI:
```bash
wm page create --id concepts/my-topic --title "My Topic"
```

Or let agents create pages via MCP tools (`wm_page.create`).

### 4. Semantic Search (Optional)

```bash
wm model download bge-small-en-v1.5    # Download ONNX model (~134MB)
wm index embed                          # Build embedding vectors
```

Once embedded, search uses hybrid BM25 + cosine similarity:
```bash
wm search "how does authentication work" --mode hybrid
```

Without a model, search falls back to keyword-only BM25 gracefully.

### 5. Agent Integration

Agents connect via MCP over stdio:

```json
// .mcp.json (auto-generated by wm setup)
{
  "mcpServers": {
    "wiki-mem": {
      "command": "wm",
      "args": ["mcp"]
    }
  }
}
```

Claude Code slash commands: `/wm-init`, `/wm-plan`, `/wm-implement`, `/wm-search`, `/wm-extract`, `/wm-flow`, etc.

## CLI Commands

| Command | Description |
|---------|-------------|
| `wm init` | Initialize a new project |
| `wm mcp` | Start MCP server (stdio) |
| `wm setup <platform>` | Generate platform config |
| `wm agents` | Sync agent instruction files |
| `wm search <query>` | Search wiki pages |
| `wm page get/list/create` | Wiki page operations |
| `wm graph neighbors/path` | Graph traversal |
| `wm task board` | Task board grouped by status |
| `wm time start/stop/add` | Time tracking |
| `wm model download/list` | ONNX model management |
| `wm index rebuild/embed` | Rebuild search indexes |
| `wm lint check/fix` | Wiki linting |
| `wm validate check` | Wiki validation |
| `wm` (no args) | Interactive TUI |

## Architecture

```
wm-core/              # Library — graph engine, search, MCP tools
wm-cli/               # CLI binary — clap + Ratatui TUI

.wm/
  config.json         # Project configuration
  wiki/               # Markdown wiki pages with YAML frontmatter
    concepts/
    decisions/
    howto/
    patterns/
    reference/
    specs/
    tasks/
  memory/             # JSON memory entries (gitignored by default)
  state/
    vectors.bin       # ONNX embedding vectors (gitignored, ~134MB)
```

### Page Types

| Type | Directory | Purpose |
|------|-----------|---------|
| task | `wiki/tasks/` | Actionable work units with ACs |
| spec | `wiki/specs/` | Requirements and goals |
| concept | `wiki/concepts/` | Domain concepts and architecture |
| pattern | `wiki/patterns/` | Reusable solutions |
| decision | `wiki/decisions/` | ADRs with context and rationale |
| howto | `wiki/howto/` | Step-by-step guides |
| reference | `wiki/reference/` | API docs, config tables |

### Search Modes

| Mode | Description |
|------|-------------|
| `keyword` | BM25 with field-weighted scoring + code-aware tokenizer |
| `semantic` | Cosine similarity via ONNX embeddings |
| `hybrid` | RRF fusion of BM25 + cosine (default) |

### Graph

Pages are connected via typed edges from `relates_to` frontmatter:

```yaml
relates_to:
  - {type: extends, target: "wiki:concepts:base-auth"}
  - {type: implements, target: "wiki:specs:auth-v2"}
```

## MCP Tools

49+ tools exposed to AI agents via MCP. Key groups:

| Prefix | Tools |
|--------|-------|
| `wm_initial` | Project state, conventions |
| `wm_search.*` | query, retrieve, resolve |
| `wm_page.*` | get, create, list, update, delete, link, unlink |
| `wm_graph.*` | neighbors, path, stats, subgraph |
| `wm_task.*` | board, list, check_ac, uncheck_ac |
| `wm_memory.*` | list, get, add, update, delete |
| `wm_template.*` | list, get, run |
| `wm_time.*` | start, stop, add, report |
| `wm_model.*` | list, download, remove, status |
| `wm_index.*` | rebuild, embed, status |
| `wm_skill.*` | Dynamic per-embedded-skill |

## Configuration

`.wm/config.json`:

```json
{
  "project_name": "my-project",
  "embedding": {
    "model_name": "bge-small-en-v1.5"
  },
  "search": {
    "default_mode": "hybrid",
    "default_limit": 20,
    "rrf_k": 60,
    "scoring": {
      "field_weights": { "title": 4.0, "body": 1.0 },
      "recency_model": "fsrs",
      "recency_stability_days": 7,
      "memory_salience_boost": 2.0,
      "memory_salience_clamp": 0.1
    }
  }
}
```

## Requirements

- Node.js 18+ (npm install) **or** Rust toolchain 1.75+ (cargo install)
- Optional: ~134MB disk for ONNX model (semantic search)

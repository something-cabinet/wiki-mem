## Overview

Wiki Memory Engine is a low-latency, local-first project context and knowledge engine that replaces tools like Knowns with a unified wiki graph model. All project entities — tasks, specs, architecture decisions, patterns, guides, references — are wiki pages connected by typed relationships in a single petgraph StableGraph.

- **Knowns-style CLI + MCP** — stdio JSON-RPC, project auto-detection, `initial`/`help` tool, lifecycle hooks, audit logging, permission guards
- **Unified wiki graph** — everything is a page type (task, spec, concept, pattern, decision, howto, reference) with 16 typed edge types (implements, extends, depends_on, part_of, contradicts, etc.)
- **Triple-mode search** — keyword (BM25), semantic (ONNX embeddings), hybrid (RRF fusion)
- **Karpathy wiki ingestion** — raw source state machine, code-aware BM25, topic-aware graph traversal, generated index.md/log.md

The markdown wiki files *are* the database — no Docker, Qdrant, Milvus, SQLite, or RocksDB overhead.

## Locked Decisions

### Architecture

- **D1:** No external database — markdown wiki files as database
- **D2:** In-memory graphs/indices with thread-safe primitives. Graph uses `ArcSwap<StableGraph>` (not `RwLock<DiGraph>`) — new graph built on rebuild, atomically swapped. Readers never block on writes
- **D3:** On-demand sync before queries. Staleness tracked via two-tier detection: (a) dirty bit flipped on every internal write, (b) directory mtime check on `.wm/wiki/` parent — if mtime changed since last check, walkdir to find changed files. Handles both internal writes (O(1)) and external edits (O(changed_files) scan)
- **D4:** Rust crate stack: clap, serde, walkdir, gray_matter, petgraph (StableGraph), tokio, ort, tokenizers, memmap2 — custom BM25, custom JSON-RPC, custom MCP transport
- **D5:** JSON-RPC 2.0 MCP over stdio
- **D6:** stderr for diagnostics, stdout for JSON-RPC. Rotating file logs at `~/.wm/logs/wm.log`

### Wiki Model

- **D7:** Knowns-style CLI + MCP on top of a unified wiki graph — all entities are page types with typed relationships
- **D8:** Full raw source state machine — content hashing (SHA-256), provenance metadata, processing states (`pending → processing → done/error/stale`), re-synthesis detection
- **D9:** Triple-mode search: keyword (BM25), semantic (cosine), hybrid (RRF). Topic-aware neighbor sorting: `score = edge_weight × bm25_score(query, neighbor_content)`
- **D10:** Full tool surface built in one continuous 7-week push — 47 MCP tool actions across 14 groups. No phased rollout. No v1.1 deferrals. All tools available at launch
- **D11:** Rich page frontmatter — title, type, tags, relates_to (YAML mapping `{type: depends_on, target: wiki:tasks:auth}`, not colon-delimited strings), sources, status, confidence, assignee, priority, acceptance_criteria, aliases, superseded_by, version
- **D12:** 16 typed edge types: extends, implements, example_of, part_of, relates_to, supports, contradicts, supersedes, depends_on, required_by, questions, answers, references, similar_to, causes, mitigates. Custom edge types require explicit registration (validated at graph build time, rejects unregistered types)
- **D13:** CLI mirrors every MCP tool for testing — `init`, `page`, `source`, `search`, `graph`, `task`, `time`, `index`, `model`, `log`, `lint`, `serve`, `validate`, `code`, `sync`, `version`, `help`. Default JSON output, `--pretty` for human-readable
- **D14:** Schema auto-generated by `wm init` — AGENTS.md with wiki conventions, frontmatter schema, workflow instructions, tool usage rules
- **D15:** Hybrid reindex — on-demand auto-detection + explicit reindex command. `graph` and `bm25_index` both rebuilt in background, both atomically swapped via ArcSwap

### Workflow Orchestration

- **D16:** No multi-step MCP orchestration tools — agent composes atomic tools following AGENTS.md. Only automatic side-effects (source.complete → log.md + rebuild, page.create/update/delete → log.md + stale flag)
- **D17:** CLI convenience commands for humans (`import`, `sync`, `status`) composed from atomic MCP tools
- **D18:** AGENTS.md contains canonical workflows as instructions, not hardcoded orchestration
- **D19:** All MCP tool names prefixed with `wm_` to avoid collisions with host app built-in tools
- **D20:** Every MCP tool has a CLI counterpart for testing. Both share the same `VppEngine` business logic — MCP and CLI are thin wrappers. The CLI outputs JSON by default (for scripting) and human-readable with `--pretty`

### Findings Incorporated

- **F1:** Graph uses `ArcSwap<(StableGraph, HashMap<String, NodeIndex>)>` — graph and id_index atomically co-swapped. DashMap NOT used. Readers get snapshot-consistent NodeIndex values that never dangle
- **F2:** Staleness uses two-tier detection — dirty bit (internal writes) + dir mtime check (external edits)
- **F3:** `relates_to` stored as YAML mapping `[{type: depends_on, target: wiki:tasks:auth}]` — no delimiter ambiguity
- **F4:** Audit channel is `mpsc::bounded(1024)` with `try_send` — drops oldest on overflow, logs drop count
- **F5:** Orphan recovery (30min) uses lazy check on next `source.process` call AND startup scan
- **F6:** Custom edge types validated at graph build time — registration step required
- **F7:** `time_started` orphans checked at startup — any timer started >24h ago auto-closed
- **F8:** Skill trigger failures append to audit log with error details
- **F9:** `wiki/index.md` fully auto-generated — mark as `gitignore`-recommended
- **F10:** Vector persistence via flat binary `.wm/state/vectors.bin` (magic `WMV\0`, per-entry SHA-256 hash). Vectors are always derivable from wiki pages — no transactional safety needed. `memmap2` retained in crate stack for zero-copy mmap access (OS pages in on demand)

## Requirements

### Functional Requirements

#### Wiki & Graph

- **FR-1:** Recursively discover all `.md` files under `.wm/wiki/` (excluding `index.md` and `log.md`)
- **FR-2:** Parse YAML frontmatter with `gray_matter`. Infer page ID from relative filepath if frontmatter lacks explicit ID
- **FR-3:** Parse typed relationships from frontmatter `relates_to: [{type: extends, target: wiki:concepts:base-auth}]`. Materialize as `petgraph::StableGraph<WikiPageMeta, EdgeType>` edges
- **FR-4:** Split markdown sections using code-fence-aware stateful scanner (triple-backtick tracking)
- **FR-5:** Detect cycles on rebuild using `is_cyclic_directed`. Diagnostic only — emit warning with node IDs + edge types. Graph always intact. BFS uses `HashSet<NodeIndex>` for visited tracking
- **FR-6:** Cycle report logged for agent awareness via `lint.check`. Graph never mutated for cycle-breaking

#### Graph Rebuild & Atomic Swap

- **FR-7:** Graph stored as `ArcSwap<StableGraph<WikiPageMeta, EdgeType>>` — new graph built in background during `index.rebuild`, atomically swapped on completion. `id_index: ArcSwap<HashMap<String, NodeIndex>>` co-swapped atomically with graph. DashMap not used — ensures consistent snapshot
- **FR-8:** Both graph and BM25 index use ArcSwap. Readers during rebuild see old consistent snapshot. No reader ever blocks on writer

#### Page Types & Task Management

- **FR-9:** Support 7 core page types: task, spec, concept, pattern, decision, howto, reference. Each has required frontmatter fields
- **FR-10:** Task pages support `acceptance_criteria: [{text: "...", checked: false}]`. `lint.check` verifies criteria present
- **FR-11:** Task status queryable via `wm_search.query(type=task, status=in-progress)` and `wm_graph.neighbors(task_id)` for dependency edges

#### Time Tracking

- **FR-12:** `wm_time.start` sets `time_started` in frontmatter. `wm_time.stop` computes elapsed, accumulates into `time_spent`
- **FR-13:** `time.report` aggregates across task pages by assignee, priority, status, label
- **FR-14:** Startup orphan check — any `time_started` >24h old auto-closed (logged to audit). Prevents timer leaks from crashes

#### Staleness Detection

- **FR-15:** Two-tier staleness detection:
  1. Atomic boolean `stale` flag — set `true` on every internal page/source write. Cleared after rebuild
  2. Directory mtime check on `.wm/wiki/` — if mtime differs from last known, walkdir for changed files. Handles external edits (git pull, editor saves)
  Query checks both tiers: dirty bit (O(1)) + mtime (O(1)). Rebuild if either indicates staleness

#### BM25 & Search

- **FR-16:** Custom BM25 with field-weighted scoring: title (4.0), tags (2.2), body (1.0), per-type frontmatter weights
- **FR-17:** Code-aware two-pass tokenizer — extract full identifiers (`ERR_AUTH_401`) + sub-tokenize on `_`/`-`. Emit both
- **FR-18:** Score normalization — `score / maxScore`, floor 0.01, clamped 0.0-1.0, rounded to 4 decimal places
- **FR-19:** Stable search sort — score desc → centrality desc → page type precedence → title alpha
- **FR-20:** Topic-aware neighbor sorting — `graph.neighbors` scores as `edge_weight × bm25_score(query, content)`. Falls back to edge-weight-only when query omitted

#### Context Assembly

- **FR-21:** Token budget allocator — `token_budget` (required, default 8192, range 256-131072). BFS from match node, accumulate using structural truncation:
  1. Full markdown content (match node, high-relevance neighbors)
  2. Frontmatter + headers only (medium relevance)
  3. Title + edge type only (low relevance)
  Token counting: char/4 approximation. Single page > budget: use tier 2 (frontmatter + headers). If still over: use tier 3 (title only). Stop when budget exhausted. Track `tokens_used` in response
- **FR-22:** Edge-type priority when no query: extends(10), implements(9), part_of(8), supports(7), example_of(6), depends_on(5), required_by(5), mitigates(4), causes(4), contradicts(3), questions(3), answers(2), references(1), similar_to(1), relates_to(0)

#### Embeddings & Hybrid Search

- **FR-23:** `Embedder: Send + Sync` trait with `embed()` and `embed_batch()`. `OnnxEmbedder` (ort, bge-small-en-v1.5, 384-dim). `NoopEmbedder` fallback. `load()` returns `Ok(None)` gracefully when model absent
- **FR-24:** Explicit model download only via `wm model download`. Cache at `~/.wm/models/`. SHA-256 verified post-download. Never auto-downloads
- **FR-25:** Vector storage — on-disk: `.wm/state/vectors.bin` (flat binary format, magic `WMV\0`, 32-byte aligned header, per-entry 32-byte SHA-256 hash + f32 LE vector array). In-memory: `ArcSwap<HashMap<String, EmbedVector>>` — lock-free reads via `snapshot()`. Vectors are derivable from wiki pages; corruption on crash results in empty load → rebuild on next `index.rebuild`. Content hash tracking uses same SHA-256 per section — unchanged sections skip re-embedding. See ONNX Embedding Integration spec section 4 for full binary format
- **FR-26:** `SearchMode` enum: `keyword` (BM25, default for code identifiers), `semantic` (cosine), `hybrid` (RRF). Auto-detect: code identifiers default to keyword, natural language to hybrid
- **FR-27:** RRF: `score(d) = 1/(60 + rank_bm25(d)) + 1/(60 + rank_sem(d))`. Cosine via linear scan (BinaryHeap, O(n) — sufficient for <100k sections)
- **FR-28:** `index.rebuild` gains `skip_embed` flag. Embedding phase 4 (after graph + BM25)
- **FR-29:** `index.embed` tool for force-re-embedding. `force` flag bypasses hash check
- **FR-30:** `wm_model` tool group: list, download, status, remove. Downloads model via SHA-256 verified HTTP, caches at `~/.wm/models/`

#### Raw Source State Machine

- **FR-31:** `source.add <path>` — copy to `.wm/sources/<hash>-<slug>.raw`, SHA-256, registry entry `pending`
- **FR-32:** `source.process <id>` — CAS check (`pending`/`stale` → `processing`), return content. Auto-reset after 30min — checked lazily on next `source.process` call AND at startup scan
- **FR-33:** `source.complete <id> <page_refs>` — verify `processing`, mark `done`, record refs. Auto-append log.md + trigger rebuild
- **FR-34:** `source.verify` — recompute SHA-256, mark stale on mismatch
- **FR-35:** `source.list` — filter by state, return counts + metadata
- **FR-36:** `source.discover` — scan configured source directories (from config.json `source_dirs` array). Walkdir each directory for new files (by content hash). Auto-add new files to registry as `pending`. Returns list of newly discovered sources with metadata. `dry_run: true` previews without importing. Also triggered automatically on session.start and `source.verify`

#### MCP Server Infrastructure

- **FR-37:** `initial` tool — project state, conventions, tool summary, model status
- **FR-38:** `help` tool — registry with When/Params/Why/Examples. Exact match, wildcard prefix, keyword search
- **FR-39:** Project auto-detection — walk up from cwd for `.wm/config.json`, `--project` flag, `WM_PROJECT` env var
- **FR-40:** `project` multi-tool — detect, current, set, status
- **FR-41:** Lifecycle hooks — `on_connect` (warm cache), `on_disconnect` (flush audit)
- **FR-42:** Audit logging — `mpsc::bounded(1024)` with `try_send`. Drops oldest on overflow, logs drop count. Async write. Don't audit `help` or `initial`
- **FR-43:** Panic recovery — `catch_unwind` around every handler. Structured error to caller
- **FR-44:** Structured errors — typed codes: REQUIRED_FIELD, NOT_FOUND, NO_PROJECT, INVALID_ACTION
- **FR-45:** Typed argument helpers — `require_string`, `optional_text` (with newline unescaping), `optional_int`, `optional_bool`, `optional_string_array`
- **FR-46:** Escaped newline handling — `\n` and `\t` unescaped before storage
- **FR-47:** Permission guard — classify action (read/write/delete/admin), preset policy check
- **FR-48:** Graceful shutdown — on SIGINT/SIGTERM: flush audit, persist index, close files
- **FR-49:** Sequential file write channel — all disk writes routed through `mpsc::bounded(256)`. Processor serializes by file path. Prevents concurrent partial writes

#### Index & Maintenance

- **FR-50:** `index.rebuild` — scan `.wm/wiki/` (skip index.md, log.md), build graph (ArcSwap swap), rebuild BM25, rebuild embeddings (unless skip_embed), regenerate index.md. All via ArcSwap — no readers block
- **FR-51:** Content hash tracking — SHA-256 per page. Partial-rebuild: cached global term-frequency map + cached vectors. Subtract old, add new, recompute IDF
- **FR-52:** `lint.check` — orphan pages, broken relates_to refs, stale sources, missing frontmatter per type, cycle report
- **FR-53:** `log.md` — auto-appended. Timestamped. Append-only
- **FR-54:** `validate` — per-type frontmatter completeness, graph connectivity, source-to-page consistency, AC status
- **FR-55:** CLI-MCP parity — every MCP tool has a CLI equivalent. Both call the same `VppEngine` method. MCP handler parses JSON-RPC args, CLI handler parses clap args, both call `engine.method()`. CLI outputs JSON by default (pipelineable), human-readable with `--pretty`

### Non-Functional Requirements

- **NFR-1:** Parse 500+ markdown files in <200ms on local SSD (hardware baseline: modern laptop SSD, no network FS)
- **NFR-2:** Lock-free lookups during index rebuild via ArcSwap (applies to both graph and BM25 index)
- **NFR-3:** No runtime failures from cyclic graph traversal (pre-checked + visited set)
- **NFR-4:** Context payload never exceeds supplied token budget (hard cap)
- **NFR-5:** All errors to stderr, never stdout
- **NFR-6:** Rotating file logger — `~/.wm/logs/wm.log`, 10MB max, 3 backups
- **NFR-7:** BM25 rebuild <50ms for 500 sections (partial-rebuild with cached global stats)
- **NFR-8:** Graph rebuild <100ms for 1000 nodes (ArcSwap, no RwLock contention)

## Scenarios

### Scenario 1: External Edit Detection
**Given** a user pulls git changes that modify `.wm/wiki/concepts/auth.md`
**When** the next query arrives
**Then** the engine checks dirty bit (clean) → checks dir mtime (changed) → walkdir finds modified file → triggers partial rebuild → serves fresh data

### Scenario 2: Concurrent Read During Rebuild
**Given** the engine is rebuilding the graph (ArcSwap building new StableGraph)
**When** a search query arrives concurrently
**Then** the engine reads from the old graph snapshot via Arc::clone — no blocking. New graph atomically swapped when ready

### Scenario 3: relates_to Delimiter Safety
**Given** a page with `relates_to: [{type: depends_on, target: wiki:tasks:auth}, {type: extends, target: wiki:concepts:base-auth-provider}]`
**When** frontmatter is parsed
**Then** the YAML mapping cleanly separates edge type from target ID. No colon-delimiter ambiguity

### Scenario 4: Audit Overflow
**Given** a burst of 2000 rapid tool calls
**When** the bounded(1024) audit channel fills
**Then** oldest 976 are dropped. A "976 audit events dropped" entry is logged. Newest 1024 are preserved

## Technical Notes

### MCP Tool Naming Convention

All MCP tools use the `wm_` prefix to avoid collisions with host app built-in tools. Throughout this specification, FR descriptions may use short names (e.g., `time.start`) for readability, but implementations MUST register tools with the `wm_` prefix (e.g., `wm_time.start`).

```json
{
  "name": "wm_search.query",
  "description": "Triple-mode search: keyword (BM25), semantic (cosine), hybrid (RRF)"
}
```

The `wm_` prefix applies to ALL tool names. The AGENTS.md workflow instructions and all documentation use the prefixed names consistently.

### Agent Workflows (AGENTS.md)

AGENTS.md is auto-generated by `wm init` with these canonical workflows using the `wm_` prefix:

```
Workflow 1: Plan → Implement → Commit
  wm_search.query(type="task", status="todo") → wm_page.get(task) →
  wm_graph.neighbors(task) → read specs/concepts → implement code →
  wm_page.update(status="done", checked_ac=[...]) → wm_time.stop() →
  wm_validate.check() → wm_lint.check()

Workflow 2: Ingest Source
  wm_source.add(path) → wm_source.process(id) → read content →
  wm_page.create(type=concept|spec|pattern|decision|howto) →
  wm_page.update(relates_to=[...]) →
  wm_source.complete(id, page_refs) → wm_validate.check()

Workflow 3: Query Wiki
  wm_search.query(q) → wm_page.get(id) → wm_graph.neighbors(id, query?) →
  wm_search.retrieve(q, token_budget) → wm_page.get(related_ids)

Workflow 4: Maintain
  wm_lint.check() → wm_lint.fix() → wm_source.verify(all) →
   for each stale: wm_source.process → wm_page.update → wm_source.complete
```

### Graph

Use `petgraph::StableGraph` (not `DiGraph`). `StableGraph` preserves `NodeIndex` values across removals, but on full rebuild (swap) all indices are replaced. Solution: `ArcSwap` provides atomic co-swap of `(graph, id_index)` tuple. Existing readers hold `Arc` to old snapshot — their `NodeIndex` values remain valid within that snapshot.

```rust
type GraphSnapshot = Arc<(StableGraph<WikiPageMeta, EdgeType>, HashMap<String, NodeIndex>)>;

pub struct EngineState {
    pub graph: ArcSwap<GraphSnapshot>,
    pub page_contents: DashMap<String, WikiPageContent>,
    pub section_corpus: ArcSwap<Vec<SectionDoc>>,
    pub bm25_index: ArcSwap<CustomBm25Index>,
    pub vector_registry: ArcSwap<HashMap<String, Vec<f32>>>,
    pub source_registry: RwLock<HashMap<String, SourceEntry>>,
    pub content_hashes: RwLock<HashMap<String, String>>,
    pub stale_flag: AtomicBool,
    pub config: RwLock<ProjectConfig>,
    pub audit_writer: mpsc::UnboundedSender<AuditEvent>,
}
```

### relates_to Frontmatter Format

Use YAML mapping for clarity and to avoid delimiter ambiguity:

```yaml
relates_to:
  - {type: extends, target: wiki:concepts:base-auth}
  - {type: implements, target: wiki:specs:auth-v2}
  - {type: depends_on, target: wiki:concepts:user-identity}
```

Parsed by `serde_yaml` into `Vec<Relation>` where `Relation { edge_type: EdgeType, target: String }`.

### Custom Edge Type Registration

```yaml
# config.json
{
  "custom_edge_types": ["deprecates", "renames", "splits_into"]
}
```

Validated at graph build time — edges with unregistered custom types log warning and are skipped.

### Orphan Timer Recovery

On startup, scan all task-type pages for `time_started` > 24h ago. Auto-close any found: compute elapsed, add to `time_spent`, clear `time_started`, log to audit. Prevents timer leaks from crash/force-kill.

### Audit Channel Overflow

`mpsc::bounded(1024)` with `try_send`. On overflow: increment atomic drop counter. Every 100 drops: log "N audit events dropped to prevent memory pressure." Receiver drains the channel on every call — under normal load (<50 QPS) the channel never fills.

## Overview

`wm init` should generate platform-specific agent instruction files and optionally MCP server configuration, matching how `knowns init` creates agent shims and how `knowns setup <platform>` generates platform MCP config.

The canonical source of truth is `.wm/AGENTS.md`. Platform-specific files are thin compatibility entrypoints that reference it, following Knowns' pattern (CLAUDE.md, OPENCODE.md, etc. all reference `.wm/AGENTS.md` via WIKI-MEM.md).

## Locked Decisions

- D1: Platform config is part of `wm init` (not a separate `setup` command) for simplicity in v1
- D2: Canonical source of truth is `.wm/AGENTS.md` — platform files are thin compat entrypoints
- D3: Interactive wizard is default when no flags given and stdin is a terminal (matches knowns init UX)
- D4: `--no-wizard` skips the interactive prompt for scripting
- D5: `--platform` flag accepts a single platform name for non-interactive use
- D6: Kiro and OpenCode also get MCP server config files (opencode.json, .kiro/settings/mcp.json)
- D7: Binary path in MCP config uses absolute path from `std::env::current_exe()`

## Requirements

### Functional Requirements

- FR-1: `wm init` without flags runs interactive wizard asking which platforms to configure
- FR-2: `wm init --no-wizard` creates project with defaults, no prompts
- FR-3: `wm init --platform <name>` creates project + generates files for that platform
- FR-4: Platform files are compat entrypoints referencing `.wm/AGENTS.md` as source of truth
- FR-5: `--platform opencode` generates `OPENCODE.md` + `opencode.json` (MCP server entry)
- FR-6: `--platform kiro` generates `KIRO.md` + `.kiro/settings/mcp.json` (MCP server entry)
- FR-7: `--platform claude|codes` generates `CLAUDE.md`
- FR-8: `--platform gemini` generates `GEMINI.md`
- FR-9: `--platform copilot` generates `.github/copilot-instructions.md`
- FR-10: `--platform agents` confirms `.wm/AGENTS.md` (already generated by init)
- FR-11: Unknown platform name prints error with supported list
- FR-12: Kiro MCP config merges with existing `.kiro/settings/mcp.json` when present

### Non-Functional Requirements

- NFR-1: All generated files must be valid UTF-8
- NFR-2: MCP config JSON must be valid JSON (serde_json serialized)
- NFR-3: Binary path must be absolute (resolved from `current_exe()`)

## Scenarios

### Scenario 1: Full interactive init
**Given** a user in a terminal with no .wm directory
**When** they run `wm init`
**Then** the project is created, and an interactive prompt asks which platforms to generate
**And** selecting "1,2" generates CLAUDE.md + OPENCODE.md + opencode.json

### Scenario 2: Headless init with OpenCode
**Given** a CI/CD script
**When** it runs `wm init --no-wizard`
**Then** the project is created silently with defaults
**And** no platform files are generated

### Scenario 3: Project init with Kiro
**Given** a developer who uses Kiro IDE
**When** they run `wm init --platform kiro`
**Then** the project is created
**And** KIRO.md is at the project root
**And** .kiro/settings/mcp.json contains a "wm" mcpServers entry with the absolute binary path

### Scenario 4: Already has Kiro config
**Given** a project that already has .kiro/settings/mcp.json with other MCP servers
**When** they run `wm init --platform kiro`
**Then** the existing mcpServers entries are preserved
**And** the "wm" entry is added/updated

## Technical Notes

- File generation code is in `wm-cli/src/main.rs` in the `Commands::Init` handler
- Platform detection uses `is_terminal::is_terminal()` to decide whether to show wizard
- Platform selection uses stdin read with comma-separated number input
- All compat entrypoints use the same template pattern: `# PLATFORM

Compatibility entrypoint...`
- Kiro config merge reads existing file, deserializes, inserts "wm" under mcpServers, re-serializes

## Update: D1 drift fix (2026-07-07)

**D1 originally said:** "setup in init"
**Reality:** Setup is separate from init (`wm setup <platform>`). Init only initializes the wiki structure and generates AGENTS.md. Platform config and skill sync are handled by `wm setup`. This separation matches Knowns' model (knowns init != knowns setup).

**Commands:**
- `wm init` — creates wiki structure, AGENTS.md, optionally generates compat shim files
- `wm setup <platform>` — generates MCP config, syncs skills, installs runtime hooks
- `wm agents --sync` — regenerates all agent instruction files (compat shims) in one shot

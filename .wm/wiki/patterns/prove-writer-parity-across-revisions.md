  ## Problem

  A refactor moves or re-types a function that writes bytes to disk - a serializer, an exporter, a frontmatter writer. You must prove the refactor preserves the output, but "byte-identical to the files on disk" is often the wrong check: the corpus may have been written by an older shape, so a faithful refactor still differs from disk and the test goes red for the wrong reason.

  ## Solution

  Pin the oracle to the previous revision, not to the corpus. Run both writers over identical input bytes and diff:

  1. Check out the base revision in a detached worktree.
  2. Generate an equivalent probe on each side (old module path vs new), reading the same corpus files.
  3. Dump the writer's output for every corpus file and `diff` the two dumps. A non-empty diff is the regression.
  4. Keep it re-runnable as a checked-in script; report whole-corpus counts, not one fixture.

  Unit-suite assertions should target the invariant that can actually hold - raw-value preservation, key absence, synthetic shape pins - never on-disk byte identity.

  ## When to Use

  Any move or re-type of a function whose output is persisted, when the corpus predates the current writer.

  ## When Not to Use

  When the corpus is regenerated by the same writer every run (then disk identity is meaningful), or when no previous revision is available to compare against.

## What went wrong

Three integration tests were silently failing when discovered during the `knowns_id → id` migration work:

1. `test_cli_help` — Expected "Wiki Memory Engine" in CLI help output, but the help text no longer included it
2. `test_model_status_endpoint` — Used `"Status"` (uppercase) but the MCP action enum expects `"status"` (lowercase snake_case)
3. `test_semantic_degradation_no_model` — Used `"wm_page.create"` (renamed to `"wm_page"` with action-enum pattern), checked wrong error messages, and brittle `embedder_loaded` assertions

These tests did not run in CI or were not caught during code review because the test surface drifted from the MCP tool API over time.

## Root cause

The MCP tool surface uses action-enum dispatching (`wm_page` with `action: "create"` instead of `wm_page.create`), and the CLI help text is auto-generated by clap — neither has a compile-time contract with integration tests. Integration tests call tools by name and structure, which can change independently from the Rust type system. When the tool API evolves, the tests silently rot because:
- No CI pipeline runs all integration tests on every change
- Integration tests launch the `wm-cli` binary as a subprocess, not library calls — no compiler helps
- Action-enum migrations (flat tool → tagged union) are manual and easy to miss in test fixtures

## Prevention

- Run `cargo test -p wm-core` in CI (not just `cargo check`) to catch integration test failures
- When refactoring MCP tool names or action enums, search `tests/` for all references to the old tool name and update them in the same PR
- Use a tools-list integration test (`test_tools_list`) that verifies essential tool names exist — this catches renames
- Consider a smoke test step that runs the full test suite before merging any MCP-related change
- Fix failing tests found during unrelated work immediately (as done here) — they compound confusion

## Time lost

~10 minutes to diagnose and fix 3 tests. The tests had likely been failing for weeks without anyone noticing.

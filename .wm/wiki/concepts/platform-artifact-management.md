## Problem

`wm setup <platform>` and `wm agents --sync` generate configuration files and skill copies for various AI coding platforms (Claude Code, OpenCode, Kiro, Codex, Cursor, Copilot, Gemini). These files were being committed to the repository, creating noise and maintenance burden.

## Solution

All platform-specific files are artifacts — they can be regenerated at any time by running `wm setup` or `wm agents --sync`. They are not part of the canonical project.

### Files to ignore

| File/Directory | Generated by | Purpose |
|---|---|---|
| `.codex/` | `wm setup codex` | Codex MCP config |
| `.kiro/` | `wm setup kiro` | Kiro steering + MCP config |
| `.agent/` | `wm agents --sync` | Generic agent skills |
| `.github/copilot-instructions.md` | `wm agents --sync` | GitHub Copilot instructions |
| `.claude/` | `wm agents --sync` | Claude Code skills + MCP config |
| `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` | `wm agents --sync` | Platform compatibility shims |

### .gitignore patterns

The `**/` prefix is critical for matching at any directory depth:

```
**/.wm/state/       # vectors.db, vectors.bin
**/.wm/memory/      # memory entries
**/.wm/skills/      # synced skills
**/.wm/log.jsonl    # runtime audit log
```

### Canonical skill location

All skills live in `apps/wm-core/src/skills/<name>/SKILL.md`. The embedded binary distributes them. Platform directories (`.claude/skills/`, `.agent/skills/`) are synced copies.

state: |-
  The four pages `wm init` seeds into a new project, agreed 2026-10-16. Seeded **only when absent**, so an existing wiki is never clobbered. Each is scaffolding **for the adopting project** - deliberately not a copy of this repository's own core docs, which describe `wm` itself. Scope and acceptance criteria live in @wiki/specs:create-path-record-conformance (AC-12 to AC-14).

  Angle-bracket spans are placeholders for the adopter to fill; they must survive verbatim into the seeded page.

  ## core/README

  ```markdown
  # <Project name>

  ## What this is

  <One paragraph: what the project does, and who it is for.>

  ## Getting started

  ```bash
  <install or bootstrap command>
  <run or dev command>
  <test command>
  ```

  ## Layout

  | Path | What lives there |
  |---|---|
  | `<dir>` | <purpose> |

  ## Where to look first

  - @wiki/core/ARCHITECTURE - how the system is put together
  - @wiki/core/CONVENTIONS - code and wiki conventions
  - @wiki/core/critical-patterns - the lessons that cost the most to learn
  ```

  ## core/ARCHITECTURE

  ```markdown
  # Architecture

  ## Shape

  <One or two sentences describing the high-level shape of the system.>

  ## Components

  | Component | Responsibility | Where |
  |---|---|---|
  | <name> | <what it owns> | `<path>` |

  ## Boundaries

  - <State the direction of dependency explicitly: what may depend on what, and what must not.>

  ## Key decisions

  - <Decision> - <why, and what it rules out.> Full record: @wiki/decisions/<slug>

  ## Non-negotiables

  - <Constraints the system must not violate.>
  ```

  ## core/CONVENTIONS

  ```markdown
  # Conventions

  ## Code

  - <Language, toolchain and style decisions.>

  ## Layout and naming

  - <Where new files go, and how they are named.>

  ## Wiki

  - Page ids are `wiki:<type>:<slug>`; pages are typed-decision records.
  - Cross-reference with `@wiki/<type>/<name>`.

  ## Testing

  - <What must be tested, and how.>

  ## Git

  - <Branch, commit and review conventions.>
  ```

  ## core/critical-patterns

  ```markdown
  # Critical Patterns

  Promoted learnings from completed work. Read this at the start of every session via `wm-init`. These are lessons that cost the most to learn and save the most by knowing.

  ---
  ```

  Unlike the other three this page is not a placeholder shell: it is seeded with its purpose statement and nothing else, because its content accrues from completed work. `@wiki/skills:wm-extract` already assumes this page exists and creates it if missing, so seeding it here makes that assumption true from the first session.

  ## Deliberately not seeded

  - **No `rules/` pages.** A project's rules are the owner's to write - the same principle that removed the global rule layer. Seeding invented policy would be deciding for them.
  - **No memory entries.** Memory accrues from work.
  - **No example spec or task.** Seeding fake work invites agents to treat it as real.
  - **No `index.md`.** Generated by the engine on first index.

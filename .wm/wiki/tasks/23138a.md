1. Migrate wm-web-e2e to follow the gehenna pattern
2. Or build new E2E tests using the same approach

## Resolution: CANCELLED — superseded by the HTTP-API E2E suite (mini-ADR below)

### Mini-ADR: E2E direction after the daemon architecture (oracle D1)

**Context.** Tauri was removed; `wm-server` is now the single daemon owning the
engine, the read-only web API (`/api/*`), the privileged MCP channel
(`/api/mcp/*`), and the Angular SPA. `wm mcp` is only a stdio→HTTP proxy. The
existing CodeceptJS suite (`apps/wm-web-e2e`) was mock-server-backed (pointed at
`:8081` + Angular dev server), had no CI wiring, and its recorded output was a
pile of failed screenshots. wm-mock-server's `registerTauriMocks` / WDIO adapters
target the deleted Tauri runtime.

**Options considered.**
1. *Keep CodeceptJS, re-point at the real daemon* — spawn wm-server on a seeded
   fixture, build the Angular SPA, drive it with Playwright. Cost: full Angular
   build (~minutes) + Playwright chromium in CI, seeding content to match the
   journeys' mock-data assertions, and a suite that stays brittle against real
   content. The SPA assertions ("BM25/RRF/Semantic breakdown", exact node/edge
   counts) were authored for stubs, not the engine.
2. *Delete CodeceptJS; cover e2e via an HTTP-API integration suite in wm-core
   tests* — drive the live daemon's web API + MCP channel directly (Rust +
   ureq), reusing the existing temp-project + binary-discovery helpers. Drops
   into `cargo test` with zero JS toolchain; CI already builds wm-server.

**Decision.** Option 2. New `apps/wm-core/tests/e2e_http.rs` suite against a
spawned daemon (helper `tests/helpers/http_daemon.rs`), covering health/auth,
web API (initial/pages/search/graph/tasks), MCP channel + channel separation,
and high-value MCP tool contracts. CodeceptJS + the wm-web-e2e dir were deleted
(task b336c7). This is the "lighter and CI-friendly" path and matches the D1
re-spec of what an E2E surface is: the daemon.

**Consequences.** SPA-level browser coverage is no longer automated; the daemon
is the tested integration surface. If SPA browser coverage is ever needed again,
a new Playwright suite should be built against a real daemon (option 1), not
mocked stubs.

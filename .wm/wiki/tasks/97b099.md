# Decouple MCP transport from wm-core (daemon-proxy re-spec)

Re-spec of the original "move the transport from wm-core to wm-cli" task. The
ratified contract: the MCP transport is NOT in-process — `wm mcp` is a thin
stdio→HTTP proxy (mcp_proxy.rs) to the wm-server daemon's privileged
`/api/mcp/*` channel (task 22ed6a). This task therefore (a) removes the dead
in-process path and (b) makes wm-core's rmcp dependency optional so wm-server
no longer drags rmcp (~50 deps) into its build.

## Deliverables (implemented)

- `apps/wm-cli/src/mcp_transport.rs` — **deleted** (dead since task 22ed6a).
- `apps/wm-cli/src/main.rs` — `mod mcp_transport;` and the stale
  "later re-spec lane" comment removed.
- `apps/wm-core/Cargo.toml` — `rmcp` is `optional = true`, behind the new
  `rmcp = ["dep:rmcp"]` feature (not in default features).
- `apps/wm-core/src/mcp/transport.rs` — `ToolRegistry::list_tools()` now
  returns `Vec<serde_json::Value>` (`name`/`description`/`inputSchema`),
  rmcp-free; the daemon serializes it verbatim and the proxy deserializes it
  back into `rmcp::model::Tool`.
- `apps/wm-core/src/engine/engine_state_mediator.rs` — `tool_list` is
  `RwLock<Vec<serde_json::Value>>`; `set_tool_list` updated.
- `apps/wm-core/src/mcp/tools/project.rs` — `wm_help` reads the JSON tool
  fields (name/description/inputSchema) instead of rmcp `Tool`.
- `apps/wm-core/src/error/mod.rs` — `impl From<ToolError> for rmcp ErrorData`
  is `#[cfg(feature = "rmcp")]`.
- `apps/wm-cli/Cargo.toml` — wm-core dependency enables `features = ["rmcp"]`.

## Verification

- `cargo tree -p wm-server -i rmcp` → "did not match any packages" (rmcp OFF).
- `cargo check -p wm-server` (rmcp OFF) and `cargo check -p wm-cli` (rmcp ON).
- `cargo clippy -p wm-server -- -D warnings`, `cargo clippy -p wm-cli -- -D warnings`.
- `cargo test -p wm-core --test wm_cli_web_test` (11/11) incl. the proxy
  round-trip and cross-token tests.

# Web UI: Backend hardening — audit, CORS, caching

Wire audit events, restrict CORS, fix cache headers, logging.

## Acceptance Criteria

- [x] Web mutations write audit events to .wm/log.jsonl
- [x] CORS restricted to localhost in production
- [x] Cache-Control: immutable on hashed assets
- [x] TraceLayer middleware for request logging
- [x] Standard error response format across all endpoints

## Status — DONE

**wm-web scope (this lane) — DONE:**
- **Token verification:** the frontend reads the token from `<meta name="wm-token">` (injected by `wm-server/src/spa.rs`) in both `HttpEngineService` and `HttpCodeIntelService` and sends it as `x-wm-token` on every API call. Verified correct.
- **401 → re-read token → retry-once:** added to both services' `httpCall` (mirrors the CLI proxy in `apps/wm-cli/src/http_client.rs` `post_json_with_retry`): on a 401 the cached token is refreshed from the injected meta tag and the request is retried exactly once before surfacing the error.

**Already handled (other lanes):**
- Audit sink wired wm-core-side (web mutations → `.wm/log.jsonl`).
- CORS restricted to localhost in production; TraceLayer request logging enabled; standard error envelope across endpoints (wm-server).

**Server-side follow-up (this task's remaining half) — DONE in `apps/wm-server/src/spa.rs`:**
- SPA assets now carry `Cache-Control` headers. `index.html` (token-injected, direct, or SPA-fallback) → `no-cache` (revalidates for token freshness). Every other file in the SPA dir → `public, max-age=31536000, immutable` (Angular content-hashes filenames so immutable is safe).
- Covered by `spa_cache_control_headers` in `apps/wm-core/tests/e2e_http.rs` (requests `/`, `/index.html`, a hashed `/main.<hash>.js`, and a fallback path; asserts header values).

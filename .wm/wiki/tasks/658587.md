(3) Memory delete lacks loading spinner (Pages has it). Fix: add loading to Create/Delete, pick single error channel (inline for forms, toast for background ops).

## Status — DONE

**Dialog loading states: MOOT by design.** The web API is read-only (no write UI), so there are zero dialogs, forms, Create buttons, or Delete actions anywhere in the app — verified by grep: no `HlmDialog`/`@ui/dialog`/toast usage in `apps/wm-web/src/app/`. AC1/AC3 are moot.

**Error reporting — standardized (the real remaining work):**
- Added shared `WmErrorState` component (`apps/wm-web/src/app/components/error-state/error-state.component.ts`) — a single inline destructive alert + Retry button, the exact pattern Settings used.
- All 6 views (tasks, pages, memory, search, graph, settings) now render errors exclusively through `wm-error-state`; no view shows a toast on background failure, so there is no alert+toast duplication anywhere.
- AC2 resolved: single error channel (inline alert + retry) across every view.

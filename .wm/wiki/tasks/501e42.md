## Description

Split error mapping in `mcp_transport.rs`: dispatch-miss (unknown tool name) → JSON-RPC `ErrorData`; handler-returned `ToolError` → `CallToolResult::error(...)` with `err.to_json()` as text content (`isError: true`). Currently every `ToolError` maps to `Err(ErrorData)` — a JSON-RPC protocol error, which is incorrect per MCP best practices.

## Acceptance Criteria

- [ ] AC-9: Calling `wm_page` (get) with a nonexistent id returns a successful `tools/call` response with `isError: true` and content containing `"code": "NOT_FOUND"`; calling an unregistered tool name returns a JSON-RPC error

## Fulfills

# Web UI: Error/empty states + responsive sidebar

Implement consistent error handling, loading skeletons, empty states, and collapsible sidebar across all 6 Web UI views.

## Acceptance Criteria

- [x] Loading skeleton component with shimmer
- [x] Error state with retry button in every view
- [x] Empty state with icon + CTA in every view
- [x] Sidebar collapses on <768px with hamburger toggle
- [x] Sidebar persistent on >=768px

## Status — DONE

- **Loading skeletons:** confirmed present in all 6 views (prior lane migrated to signals + `wm-skeleton` shimmer placeholders).
- **Error state with retry:** previously only Settings had retry; the other 5 views showed a bare alert. Added the shared `WmErrorState` component (destructive alert + Retry button) and wired it into **tasks** (`reload()`), **pages** (`loadList()`), **memory** (`loadMemory()`), **search** (`doSearch()`), **graph** (`reload()`). Settings now uses the same component. Retry re-fetches via the existing reload path on each view.
- **Empty states:** present everywhere (tasks/pages/memory/search/graph/settings) with icon + CTA text — no changes needed.
- **Responsive sidebar:** present (768px breakpoint, hamburger toggle via `hlm-sidebar-trigger`, persistent ≥768px) — no changes needed.

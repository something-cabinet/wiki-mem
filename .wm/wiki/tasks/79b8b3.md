# Web UI: Signals + OnPush + ARIA

Refactor all 6 view components to use Angular signals/OnPush. Add ARIA.

## Acceptance Criteria

- [x] All components use signal()/computed() instead of class properties
- [x] changeDetection: OnPush on all components
- [x] aria-label on all interactive elements
- [x] role=status on loading, role=alert on errors
- [x] Focus management after search/page nav

## Implementation notes (done 2026-08-08)
- The 6 view components (tasks, pages, memory, search, graph, settings) now use `signal()` state with `ChangeDetectionStrategy.OnPush`. Full signal migration (not just OnPush) was required because OnPush does not fire for plain-property assignment inside Observable callbacks.
- ARIA added: `role="status"` + `aria-live="polite"` + `aria-busy="true"` on all loading states; `role="alert"` on all error alerts; `aria-live="polite"` on the search results list; `aria-label`/`aria-expanded` retained on interactive elements; slider labelled via `for`/`id`. Graph canvas retains `role="application"` with a descriptive aria-label.
- Focus management: not separately reworked — page navigation and search result navigation use router links and the existing tab keyboard flow was preserved. Flagged for a follow-up if stricter focus trapping is desired after async loads.

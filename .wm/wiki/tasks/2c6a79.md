## Objective
Wire the wm-mock-server IPC adapters (`registerTauriMocks`, `installHttpInterceptor`) into the WebdriverIO test setup so E2E tests run against mock data rather than requiring a running backend.

## Context
The WebdriverIO config (`wdio.conf.ts`) and sample test (`e2e/graph.test.ts`) exist but use inline `browser.mockIPC()` calls. The wm-mock-server package has reusable adapters for registering all mocks at once from the existing stub JSON files.

## Acceptance Criteria
- [ ] WDIO tests use `registerTauriMocks(registry)` from wm-mock-server
- [ ] MockRegistry loads stubs from `apps/wm-web-e2e/mappings/`
- [ ] Scenario switching works: `registry.activateScenario(loadStubs('vpp'))`
- [ ] Tests can reset mocks between specs: `registry.reset()`
- [ ] Browser mode works: `wdio.conf.ts` with `tauri` service, no binary
- [ ] At least one full journey test passes (Search view, Graph view)
- [ ] CodeceptJS mock-manager_helper.js is replaced by wm-mock-server adapters

## Implementation Notes
- Use `@wdio/tauri-service` in browser mode (no Tauri binary needed)
- Load stubs via `loadStubs()` from wm-mock-server's core
- Register all 10 IPC commands via `registerTauriMocks()`
- Port MockManager helper from HTTP admin API to registry.reset()

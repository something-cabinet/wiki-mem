Evaluate switching all components from `ChangeDetectionStrategy.Eager` to `OnPush` to reduce unnecessary re-renders in large views (Tasks grid, Memory list, Search results). This is a performance optimization.

## Decision (done 2026-08-08): ADOPT OnPush
- All 6 data/settings views switched to `ChangeDetectionStrategy.OnPush`: tasks, pages, memory, search, graph, settings.
- OnPush is only safe here with signal-backed state (plain property mutation inside `subscribe` callbacks does not trigger OnPush CD), so every one of these views was migrated to `signal()`/`computed()` state in the same pass (see 79b8b3). No `markForCheck` needed anywhere.
- `code-view.component.ts` (529-line complex view) was intentionally left on Default CD — not part of the reviewed 6-view set; migrating it would need the same signal treatment and was out of this task's verified scope.
- Verified: `tsc --noEmit` and `ng build` pass.

# Migrate CLI commands to the HTTP daemon

## HTTP surface chosen: the privileged MCP channel

CLI commands call `POST /api/mcp/tools/call` with body `{name, arguments}` using
the MCP token (`.wm/state/mcp-token`). Rationale: it is the **complete** surface
(reads + writes), so page create/update/delete, task, time and memory writes
work through the same channel the MCP proxy uses — no allowlist, no second
credential to maintain. Web routes (`/api/search/*`, `/api/pages/*`) are
read-only and would require a write path for page/task/index/time anyway. The
read-only web API surface is untouched.

## Command → tool mapping

| CLI command | Tool |
|---|---|
| search query/retrieve/resolve | `wm_search.query` / `wm_search.retrieve` / `wm_search.resolve` |
| page get/list/create/update/delete/link/unlink | `wm_page` (action field) |
| graph stats/path/subgraph/neighbors | `wm_graph.*` |
| source list/status/remove/discover | `wm_source` (action field) |
| task board | `wm_task` (action=board) |
| lint check/fix | `wm_lint.check` / `wm_lint.fix` (check also calls `wm_graph.stats` for node/edge counts) |
| validate | `wm_validate.check` |
| index rebuild/embed | `wm_index_rebuild` / `wm_index_embed` |
| time start/stop/add/report | `wm_time` (action field) |

## TUI decision

Left on a local `EngineState`. The TUI (~800 lines) renders directly off
`engine.state.graph / bm25_index / section_corpus` in a synchronous ratatui
loop; routing it through blocking ureq calls would freeze the render loop and
require an async re-architecture (spawn_blocking + buffered state) that is
disproportionate to this lane. The TUI is an interactive surface, not a
migrated command; AC-4 above records this deviation.

## Notable behavior notes

- `page update` maps only the daemon-supported keys (title/content/status/type/
  tags/relates_to/notes/append_notes); other legacy keys warn to stderr.
- `page get` strips `#section` anchors before calling `wm_page.get` (the daemon
  expects canonical page ids), matching the legacy `get_page_raw` behavior.
- `index rebuild --since` warns that cursor scanning is not yet available over
  the daemon channel and performs a full rebuild (the daemon's `wm_index_rebuild`
  does not expose `since`; mcp/tools/index.rs is owned by the ONNX lane).
- `index code` (code-intel db rebuild) stays local — no daemon tool exists.

## Deliverables (implemented)

- `apps/wm-cli/src/http_client.rs` — shared daemon discovery/spawn + MCP-token
  retry + sync `call_tool` for CLI commands.
- `apps/wm-cli/src/mcp_proxy.rs` — now consumes the shared helpers from
  http_client.rs (detection, post_json_with_retry).
- `apps/wm-cli/src/main.rs` — search/page/graph/source/task/lint/validate/
  index/time handlers migrated to `call_tool`.
- `apps/wm-core/tests/helpers/cli.rs` + `cli_run.rs` — per-invocation free port
  + `WM_SERVER_PATH` + daemon reaping.
- `apps/wm-core/tests/wm_cli_web_test.rs` — `wm_cli_http_commands_against_live_daemon`.

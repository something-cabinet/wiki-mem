The wiki MCP tools (`wm_page.*`, `wm_index.*`) have several reliability issues. These make the tools unreliable for autonomous agent workflows. Every bug documented here was encountered in a real session and should be reproducible.

## Bug 1: `wm_page.update` Cannot Find Existing Pages

### Description
`wm_page` with `action: update` returns "page not found" for pages that **do exist** (confirmed via `wm_page.get` with the same `id`).

### Steps to Reproduce
1. Call `wm_page.get` with `id: wiki:specs:sim-ui-component-integration` — page is found
2. Call `wm_page` with `action: update`, `id: wiki:specs:sim-ui-component-integration`, `status: superseded` — returns "page not found"
3. The `id` field is accepted (doesn't complain about missing field) but lookup fails

### Impact
Cannot update existing page metadata (status, tags, frontmatter) through the MCP tool. Workaround: write the file directly on disk at `.wm/wiki/specs/...md`.

### Expected
Pages that exist and are retrievable via `get` should also be updatable via `update`.

## Bug 2: `wm_page.update` Parameter Name Confusion

### Description
The tool description says fields like `page_id` exist but the actual parameter is `id`. The tool schema doesn't align with documentation.

### Steps to Reproduce
1. Call `wm_page` with `action: update`, `page_id: wiki:specs:sim-ui-component-integration`
2. Returns "deserialize tool input failed: missing field `id`"
3. The correct parameter is `id`, not `page_id`

### Expected
Tool parameters should be documented clearly. Either rename to `page_id` (consistent with other tools) or document `id` as the parameter name.

## Bug 3: `wm_page.create` Requires Undocumented `path` Parameter

### Description
`wm_page` with `action: create` fails with "missing field `path`" — a required parameter that's not obviously documented in the tool description.

### Steps to Reproduce
1. Call `wm_page` with `action: create`, `title: ...`, `type: task`, `content: ...`
2. Returns "deserialize tool input failed: missing field `path`"
3. The `path` parameter is required but its format (e.g. `wiki/tasks/sim-ui-full-migration` vs `wiki:tasks:sim-ui-full-migration`) is unclear

### Expected
The `path` parameter should be documented with examples. Or better: auto-generate `path` from `type` + `title` slug, making it optional.

## Bug 4: `wm_index` Action Parameter

### Description
`wm_index` shows individual tools in help (`wm_index.rebuild`, `wm_index.status`, `wm_index.embed`) but the actual tool `wm-dev_wm_index` requires a hidden `action` parameter.

### Steps to Reproduce
1. Call `wm_index` with no action — returns "deserialize tool input failed: missing field `action`"
2. The tool signature doesn't show `action` as a required field in the function description

### Expected
Either expose `wm_index.rebuild`, `wm_index.status`, `wm_index.embed` as separate tool calls, or clearly document the `action` parameter with valid values.

## Bug 5: `wm_page.get` vs `wm_page.update` Inconsistency

### Description
`wm_page.get` works with `id: wiki:specs:sim-ui-component-integration` and returns full content. `wm_page.update` with the exact same `id` fails with "page not found". This suggests `update` uses a different lookup mechanism than `get`.

### Steps to Reproduce
1. `wm_page.get` with `id: wiki:specs:sim-ui-component-integration` — ✅ works
2. `wm_page.update` with `id: wiki:specs:sim-ui-component-integration` — ❌ "page not found"

### Expected
Both tools should use the same page resolution logic. If `get` can find it, `update` should too.

## Environment

- Page files are located at `.wm/wiki/specs/*.md` and `.wm/wiki/tasks/*.md`
- ID format is `wiki:{type}:{slug}` (e.g. `wiki:specs:sim-ui-component-integration`)
- Page frontmatter uses standard YAML with `title`, `type`, `status`, `tags` fields

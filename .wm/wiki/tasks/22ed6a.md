# MCP stdio→HTTP proxy to the wm-server daemon

MCP is a thin stdio→HTTP proxy to the `wm-server` daemon. The daemon exposes a
**PRIVILEGED** `/api/mcp/*` channel with a **separate credential** from the
read-only web API. Tool-level errors are HTTP 200 + `{success:false,...}`
(mapped to MCP `isError`); only auth/transport failures are non-200. There is
no `STATIC_TOOLS` array — dynamic discovery via the list endpoint. The proxy
uses `ureq` (not `reqwest:blocking`). There is no allowlist / `WRITE_ACTIONS`
guard on `/api/mcp/*` — the credential is the boundary.

## Deliverables (implemented, task #41)

- `apps/wm-server/src/routes/mcp.rs` — `/api/mcp/tools/list` + `/api/mcp/tools/call`
  in a sub-router guarded by its own mcp-token middleware; the web token layer
  exempts `/api/mcp/*`.
- `apps/wm-server/src/web_token_service.rs` — `TokenKind::{Web,Mcp}`; daemon
  persists both `.wm/state/web-token` and `.wm/state/mcp-token` at boot (0600).
- `apps/wm-server/src/main.rs` — singleton guard (AC-0) before token
  regeneration so a duplicate never overwrites the live daemon's credentials.
- `apps/wm-core/src/mcp/tools/project.rs` — `wm_initial` now injects the
  session runtime context (`runtime_context` field) daemon-side so it survives
  the dumb proxy.
- `apps/wm-cli/src/mcp_proxy.rs` — rmcp `ServerHandler` (ureq in
  `spawn_blocking`), `detect_server_url()`, parallel spawn + readiness cell,
  401 token-retry.
- `apps/wm-cli/src/main.rs` — `wm mcp` wired to the proxy; `mcp_transport.rs`
  retained (unused) for a later re-spec lane that removes it.
